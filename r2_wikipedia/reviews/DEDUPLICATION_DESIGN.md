# Cross-pack event identity: findings and safe implementation plan

Status: **fail-closed independent-ID mitigation implemented in source; broader identity design remains open**. No duplicate has been removed or merged. The mod bootstrap no longer auto-groups any IDs by proximity. It preserves all distinct IDs and fresh forks suppress the pivot ID, but it does not rewrite previously saved suppressions. The original heuristic builders remain for compatibility. This is not proof of saved-world compatibility, and different records sharing an ID can still be suppressed together.

## Why this needs care

- Wikipedia century entries can have a midpoint year while decade or Wikidata packs contain the correct year. Sometimes their coordinates, precision, categories, descriptions or game effects differ. Exact name equality does not establish identity, and the same event can have different names. A volcano and a tsunami resulting from it may need distinct effects even if related.
- Event IDs are persisted: `WorldStateManager` stores suppressed event IDs and branch divergence IDs; `TimelineManager` restores these. `ChronosCodexData` and `NewsService` resolve names or locations by scanning `HistoryGazetteer.allEvents()`. `FixedPointRegister` declares some IDs explicitly, and scenario lookups also use IDs. Simply deleting or hiding a duplicate could break saved branches, named chronicle entries or references.
- `NewsIndex.Event` currently has no event ID and builds its own file-based index. `Disasters` separately reads the hazard pack and interprets fields such as kind, severity and effects. Gazetteer-only deduplication would not deduplicate all displays or disaster simulation.
- The `SiblingIndex` legacy heuristic groups pins by proximity and overlapping years, then treats that relationship as identity. `TimelineManager` suppresses the whole group when a branch stops one ID. The bootstrap now uses an independent-ID index instead. **Place and year alone are not sufficient evidence of identical events.**

## Reproducible false identity example

Run `bash r2_wikipedia/probe_sibling_audit.sh` (requires JDK 17 and Gson as documented in README). It compiles the actual `HistoryGazetteer`, `SiblingIndex` and `BranchSuppression`, uses the shipped resource tree and headless stubs, and examines a sample of 1898 entries sharing a broad France reference point. Under the old one-argument builder, the Chamber of Deputies elections (`wpr_c5ddcd7ba5`) and Colonel Henry's death (`wpr_946ba04772`) are in a **30-record** proximity cluster, despite being distinct events. With regional IDs excluded, the probe verifies that the two are independently resolvable and a new simulated branch suppresses its pivot, not the other event. It also tests suppression ancestry, a simulated previously saved set and unchanged local grouping. Actual TimelineManager restoration reads and applies saved IDs directly, but was not executed in the probe. Neither the changed SimulationEngine bootstrap nor a real saved world has been tested in Minecraft. The 30-record count is only the restricted sample.

A full-tree audit (`bash r2_wikipedia/probe_sibling_audit.sh full`) found that even the intermediate regional-exclusion heuristic produced 13,906 groups containing 45,439 distinct IDs. Its largest group had 356 IDs spanning start years 1908–2026, including unrelated weather and space-launch records; transitive union joined them. These are grouping statistics, not a count of errors or real duplicates. The runtime now uses `buildIndependent`, retaining all 129,128 distinct IDs without inferred groups. The heuristic and exclusion-aware builders remain available for compatibility but are not used by the production bootstrap.

Tradeoffs: genuine same-event pins no longer automatically suppress together. Previously saved over-suppressed IDs and inherited suppressions are deliberately left intact and require a separate migration decision. Different rows that share the **same** ID still suppress together. `audit_duplicate_event_ids.py` found 34 duplicated IDs across 69 rows in 129,163 indexed event rows (32 of those ID collisions are within the storms pack, two between world and nature packs). Some storm rows have different years or different ocean basins; not every same-ID pair is necessarily an error. The full sibling probe demonstrates that suppressing `q272450` hides both its 1953 and 1954 storm rows via actual Gazetteer queries and BranchSuppression. Full row snapshots and pack positions are in `duplicate_event_ids.json` for review. Never silently renumber these IDs: their ambiguous saved-world meanings need a migration and rollback design.

`probe_timeline_manager.sh` exercises actual `TimelineManager`, `SiblingIndex`, `BranchSuppression`, Gazetteer filter and scenario control flow on synthetic fixtures. It verifies a fresh fork, a child, synthetic scenario progression and restoration of old direct/inherited IDs through an **in-memory WorldStateManager stub**; it does not exercise actual persistence serialization, the changed SimulationEngine bootstrap or Minecraft gameplay.

## Proposed fail-closed path

1. Maintain an explicit, source-reviewed identity group with stable old IDs, pack names, old records, sources, confidence, date/location precision, relationship and review notes. Distinguish same-event aliases from broader causal relationships and separate event aspects. Require one canonical choice **per consumer and effect**, not one choice for every system. Do not infer identity from names, dates or coordinates alone.
2. Validate against every indexed pack: exact expected old rows; unique IDs scoped to packs; no missing targets, cycles, contradictory groups, unreviewed or uncertain identity claims; preservation of all differing factual assertions and separate effects. Version the manifest and make changes reversible.
3. Design an alias-aware ID resolver that preserves a way to resolve legacy IDs and names. Test existing branch saves, fixed-point/scenario references, divergence pivots, ancestor suppression and chronicle/name/location rendering. Do not rewrite old saved suppression sets silently. Explicitly decide how old already-suppressed aliases affect a canonical event while retaining the original saved IDs and handling previously over-suppressed records. Test rollback and missing/invalid manifests.
4. Replace proximity-only sibling identity with verified relationships or narrow it conservatively, but first test legitimate multi-site events, fresh branches, restored branches, divergence and scenarios. Review the deliberate behavior change and migration of old saves. Do not promise this preserves all legacy behavior without tests.
5. Carry IDs and alias decisions through Gazetteer, year-only NewsIndex, dated news, maps and independent hazard systems as applicable. Avoid duplicate news without silently collapsing two differently scoped effects. Prove unrelated entries and name/date/location precision are preserved.
6. Stage a tiny batch in a copied resource tree; test the actual classes and compare all unaffected records, indices and branch behavior. Then run a full mod build and saved-world gameplay tests before claiming compatibility.
